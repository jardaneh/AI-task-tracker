# Personal AI Coding Playbook

## 1. When I reach for AI first

- For drafting all kinds of documentation based on a list of notes; including technical documentation like requirements/user stories, design & architecture documents, etc... Or even just building a document structure with placeholders to be replaced with my text.
- Generate code of medium size that handles a specific task or tests something. Going for large chunks of code will make reviewing and testing it tedious.
- Inspect a chunk of code for debugging purposes, review, identify problems including security threats, etc... The code could be authored by myself or someone else.

## 2. When I do not reach for AI

- Make a final decision and writing technical documentation describing it.
- Reviewing items generated by AI and testing them.
- Handle trivial fixes to code or documentation that are too minor to sacrifice time or effort on AI.

## 3. My non-negotiables

- Share any private information or data in an AI chat prompt or with an AI agent.
- Have AI take ownership or act as a stakeholder.
- Take any AI generated output at face-value without atleast reviewing evidence AI has specified for that output.

## 4. My review rules

- Ensure AI tool is capable of reading the contents of documents specified and not just making assumptions based on the document's name or past interaction. In several occasions, code implementing new endpoints was placed in a file named "tasks.py" under a folder called "routes" which is actually unused with the file named "main.py" holding all endpoint related code.
- Avoid long conversations or threads that can create clutter and confusing output from AI tools. Starting new threads or conversations can reap more focused output that is easier to review. In one occasion, previously specified constraints were used with a more recent prompt.
- Use AI to help in classification and triage of multiple items in question. This helps in sorting out which issues require immediate attention and which can be left for later or even ignored. For example, Codex was used in the last module of the course to carry out triage on security concerns put forward by it.

## 5. What I am still figuring out

- How can I reduce the amount of text to include in a prompt when the main task in the prompt is to review the results of another prompt that can be long? In many occasions I found it hard to distinguish what an AI tool has maintained from previous prompts within the same conversation or thread and what it actually did respond to those prompts.
- How can I ensure AI agents have full access to specific parts of a machine and no access at all on others to reduce _asking for permission_ prompts when asking for tasks and have safeguards against serious security breaches or corruption of the machine? Allowing Codex for example to access my entire file system and execute any process on the machine seems very risk. It also can drive one insane with lots of prompts asking for permissions to read/write files among other activities.

## Decision Card

- For a new feature I reach for: **ChatGPT**
- For a code review I reach for: **Github Copilot/CortexIDE**
- For debugging I reach for: **Github Copilot**
- For infrastructure I reach for: **Claude Code**
- I will never paste private or personal information into an AI tool. A list to include _all_ such things isn't possible; but it can include: full names of actual people, their business roles the names of their employers, addresses and contact information such as emails and phone numbers, passwords, security tokens, 2FA codes and any authentication related codes or strings, proprietary technical details or code that is not meant to be publicly available and anything described in an NDA signed by a user of the AI tool.
- My one rule is: I'm the boss. I must take full responsibility for the outcomes of how I use AI. I should never come off blaming AI for any mishap provided I'm careful with the way I use it and always review, test & verify the AI results.
